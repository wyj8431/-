# 登录弹窗视觉还原设计规格

**日期：** 2026-08-18
**状态：** 已获用户确认，待实施

## 1. 目标

依据用户提供的四张参考图，还原首页登录弹窗的品牌侧栏、表单布局、登录方式切换、第三方登录图标和底部协议栏。现有手机号验证码登录接口与会话恢复逻辑保持不变。

## 2. 视觉范围

弹窗使用固定遮罩和居中的白色双栏面板：

- 左栏为 All+poster 品牌宣传区，使用参考图中的高饱和蓝色、几何圆形纹理、白色品牌标识、手写感主标语和六条权益说明。
- 右栏为白色交互区，保留右上角关闭按钮和登录方式切换提示，标题、字段、按钮、分隔线和协议栏按参考图对齐。
- 桌面端维持左栏约 36%、右栏约 64% 的比例，面板宽度约 1140px；窄屏下改为单栏，左侧权益区缩短并保持表单可滚动。
- 所有按钮、输入框和图标槽位使用稳定尺寸，状态切换不能造成面板跳动。

## 3. 四种状态

`LoginDialog` 使用单一状态机管理 `phone`、`qr`、`password`、`register` 四种视图：

1. **手机验证码登录：** 手机号输入、短信验证码输入、获取验证码、登录按钮、账号密码切换入口和第三方图标行。
2. **微信扫码安全登录：** 二维码区域、扫码问题入口、手机号验证码切换入口和第三方图标行。二维码继续使用现有前端演示占位，真实微信回调留在后续身份子阶段。
3. **账号密码登录：** 邮箱/手机号、密码、登录、手机验证码切换和忘记密码入口，保持参考图的视觉结构。当前后端没有密码登录接口，点击提交时显示明确的后续开放提示，不伪造成功登录。
4. **注册账号：** 手机号、验证码、获取验证码、密码、确认密码和立即注册按钮，保持参考图的视觉结构。当前产品采用手机号验证码首次验证自动注册，不新增密码注册接口；提交时引导回手机号验证码登录流程。

关闭按钮、切换入口、协议和隐私政策入口都必须可键盘访问。表单错误与加载状态继续使用现有 `error`、`loading` 属性。

## 4. 图标资源

第三方图标顺序固定为：

1. 手机
2. QQ
3. 微博
4. 微信
5. 钉钉
6. 百度

图标全部以本地 SVG 资源进入前端构建，不依赖 CDN 或运行时外链。每个图标保留可读的 `aria-label`，品牌图标不存在时不得退化为字母或破损图片。通用关闭、二维码、手机等非品牌图标优先复用 `lucide-vue-next`。

## 5. 交互与接口边界

- 现有 `login` 事件只从手机验证码登录状态提交，并继续调用 `/api/v1/auth/login`。
- `LoginDialog` 的 `login` 事件 payload 保持 `{ phone, verificationCode }`，不改变首页的待执行模板意图恢复。
- 账号密码、扫码和注册状态只实现参考图所需的视觉状态与切换行为；真实密码登录、微信 OAuth 和独立注册接口不在本次范围。
- 新手机号继续通过验证码登录完成自动注册，页面不对用户承诺后端不存在的密码注册流程。

## 6. 组件与测试

- 修改 `poster-client/src/features/auth/LoginDialog.vue`，保持父组件事件契约不变。
- 增加本地登录品牌图标资源目录，并以可维护的映射渲染第三方图标。
- 扩展 `LoginDialog.spec.ts`：验证四种状态标题和关键字段、切换入口、图标 `aria-label`、手机号提交 payload、加载禁用和错误展示。
- 使用桌面与移动 Playwright 截图检查弹窗比例、遮罩、滚动、图标不破损和文本不溢出。

## 7. 验收标准

- 四种状态与参考图的结构、颜色层级、左右比例和主要间距一致。
- 第三方图标按“手机、QQ、微博、微信、钉钉、百度”顺序显示，均为本地真实 SVG。
- 手机验证码登录流程、加载态、错误态和登录后原意图恢复测试继续通过。
- 账号密码、扫码和注册状态可切换且不会错误调用不存在的后端接口。
- 390px 移动宽度下弹窗内容可滚动、按钮和字段完整可见，无横向溢出。
