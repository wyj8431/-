# All+poster 总需求与分期路线图

## 1. 文档目的

本文件汇总用户随后补充的任务工单和截图需求。它是产品需求池与分期决策记录，不替代当前已批准的工作台与模板发现规格，也不授权直接开始支付、协作或自由画布开发。

需求来源中的网站截图、竞品地址、React/Redux/Tailwind 选型和工时估算只作为功能与交互参考。All+poster 保持已确定的 Vue 3、TypeScript、Pinia、Fabric.js、Java 21、Spring Boot、MySQL 和 MinIO 技术方向；不复制第三方品牌、页面文案、模板、图片或代码。

## 2. 当前基线

当前最小可验证目标仍是：商家从已发布模板开始，填写允许修改的内容，上传图片，保存设计稿并导出 PNG/JPG。

已实现的服务端基础能力包括手机号验证码登录、JWT、设计稿版本冲突保护、租户隔离、设计稿 ACL、已发布模板查询、安全素材上传和 Swagger 文档。

已批准但尚未开始实施的子项目为工作台首页与模板发现。其范围限于首页、分类/标签/搜索、模板详情、创建设计稿确认和响应式展示；不包含编辑器、工作空间、会员、客服或协作。

## 3. 工单与截图需求清单

### 3.1 身份、权限与管理

来源：登录 RBAC 工单、截图。

- 手机号验证码登录。
- 微信登录适配器和扫码登录入口。
- Access Token 自动刷新、失效后的统一登录跳转、登录后返回原意图。
- 平台角色：管理员、运营、普通用户。
- 租户内设计稿角色：OWNER、EDITOR、VIEWER。
- 路由、页面、按钮和服务端接口均按权限控制；前端隐藏不等于服务端授权。
- 管理员维护模板、分类、素材和运营位；管理员不默认读取商家私有设计稿。
- 全局异常、参数校验、审计日志、API 在线文档和在线测试。
- ToC 创作端、ToB 管理端、Java 服务端分别部署，经 Nginx 统一代理。

现有采纳：手机号登录、JWT、设计稿 ACL、参数校验、统一错误、Swagger 和租户隔离。
后续缺口：刷新令牌、微信授权、平台运营角色模型、权限管理界面、管理端、审计查询和前端路由守卫。

### 3.2 海报文字与图片编辑

来源：海报文字图片工单。

- 文本框添加、选择和编辑。
- 文本内容、字体、字号、颜色、粗体、斜体、下划线、水平/垂直对齐和行距调整。
- 图片上传、替换、裁剪、缩放、旋转、水平/垂直翻转。
- 图片旋转范围为 -180 到 +180 度。
- 图片透明度、灰度、亮度和对比度等受控滤镜。
- 编辑、预览与导出使用同一份 DesignSchema，所有操作实时反映到画布。
- 对高分辨率图片的裁剪、缩放和旋转需保持可交互，不能在主线程产生持续卡顿。
- Chrome、Firefox、Safari 和 Edge 的核心编辑与导出回归验证。

与当前基线的关系：

- 管理员模板编辑器可拥有完整画布工具。
- 商家当前只修改模板开放字段，避免破坏布局并保证三分钟出图目标。
- 工单要求商家自由添加和调整任意元素，这与当前受控填写模式冲突，必须在下一份编辑器规格中明确商家编辑边界后才实施。
- 元素数据仍保存为版本化 DesignSchema JSON；不能为每个文本框或图片框创建数据库表。

### 3.3 列表与瀑布流性能

来源：虚拟列表工单、截图中的首页瀑布流需求。

- 固定高度虚拟列表：渲染视口与 overscan 范围内的条目，滚动时回收不可见 DOM。
- 不固定高度虚拟列表：测量条目高度，维护偏移量和滚动锚点，避免加载或卸载时跳动。
- 支持鼠标滚轮、滚动条拖动、键盘导航和异步分页/无缝加载。
- 加载、空状态、错误重试和占位骨架必须保持稳定布局。
- 目标：长列表滚动可用、可见项目正确加载/卸载、主流浏览器中滚动目标为每秒 60 帧。
- 通过性能报告记录 DOM 节点数量、滚动帧率、加载时间和内存趋势。

采用条件：

- 当前模板搜索接口每页最多 48 个项目，首个工作台不需要上虚拟列表。
- 当一个可滚动列表或瀑布流同时展示超过 100 个项目，或性能测量显示普通分页无法满足体验目标时，创建独立的虚拟化子项目。
- 图片瀑布流优先选择经验证的 Vue 虚拟化库；不手写动态高度算法作为首版基础设施。

### 3.4 多人协作与在线客服

来源：截图。

- 多人协作编辑、在线状态、元素或区域锁定、冲突提示、版本历史和恢复。
- 客服入口、会话或工单记录、未读状态和运营处理台。

分期边界：

- 协作建立在设计稿 ACL、不可变版本、冲突处理和编辑器稳定后。
- 首个协作版本使用服务端会话、存在状态和短时元素锁；不在第一版实现 CRDT 自动合并。
- 客服先采用可配置外部客服链接或轻量工单，只有在有明确运营流程时再建设实时聊天。
- 二者均不属于工作台模板发现阶段。

### 3.5 会员、VIP 素材与订购

来源：会员订购工单、截图。

- 至少三种可配置会员方案，展示价格、周期、权益、模板/素材下载额度、授权范围和可用工具。
- 会员权益对比、扩展工具清单、商用授权说明、富文本规则展示。
- VIP 素材和高分辨率宣传海报等受限资源。
- 会员保存/导出额度和非会员免费额度。
- 年限选择、赠送月份、价格计算、订单创建、支付跳转、支付回调、退款/取消状态和订单查询。
- PC 与移动端可读的权益对比和购买流程。

尚未确定的业务规则：

- 截图提到非会员每天三次免费保存，但必须确认它限制的是保存、导出还是两者。
- 每日额度的时区、游客与登录用户的计数口径、失败任务是否扣次数、资源下载与导出是否共用额度尚未定义。
- 支付服务商、商户主体、支付回调地址、退款责任和发票流程尚未提供，未得到这些信息前只能实现模拟结算，不能接入真实收款。
- 会员授权不替代设计稿 ACL；权益判断和租户资源权限必须分别执行。

### 3.6 运营、平台与研发交付

来源：截图。

- 首页轮播、专题位、模板瀑布流、用户信息和运营位管理。
- ToC 创作端、ToB 管理端和 Java 服务端的独立构建/部署配置。
- API 在线文档、请求示例、在线测试与健康检查。
- MySQL 本地 MCP 用于开发期受控数据库查询。
- 每日开发记录、阶段进度、已使用技能、测试结果和风险说明。

安全边界：

- MySQL MCP 只允许本地开发环境，默认只读，使用最小权限数据库账号，不连接生产库，不在聊天或日志中泄露密码。
- 研发过程记录是项目治理要求，不是最终用户可见的产品功能。
- 运营轮播和专题使用 All+poster 自有或已获许可的素材，不使用参考网站图片。

## 4. 推荐分期

| 阶段 | 目标 | 包含内容 | 不包含内容 |
| --- | --- | --- | --- |
| P0 | 工作台与模板发现 | 当前已批准的工作台计划、公开模板检索、首页专题、设计稿创建确认 | 编辑器、会员、协作、客服 |
| P1 | 身份与后台基础 | 刷新令牌、微信登录适配器、平台运营角色、管理端壳、审计与权限管理 | 实时协作、真实支付 |
| P2 | 模板编辑与受控填写 | 管理员文字/图片编辑器、字段配置、商家模板填写、浏览器 PNG/JPG 导出 | 商家完全自由画布，除非单独批准 |
| P3 | 自由创作与性能 | 商家自由画布边界、撤销/重做、图层、图片滤镜、虚拟列表/虚拟瀑布流 | 自动协作合并 |
| P4 | 协作与运营服务 | 在线状态、锁定、版本恢复、客服工单、运营位管理 | CRDT 自动合并 |
| P5 | 商业化 | 会员权益、VIP 素材、配额、订单、模拟支付，随后才评估真实支付 | 未获授权的真实收款 |
| P6 | 智能与高级生产 | AI 工具、批量创作、异步服务端导出、印刷或第三方发布 | 未经验证的大规模服务拆分 |

每个阶段必须单独完成：范围规格、数据模型、API 契约、权限/额度边界、测试策略、验收场景和实施计划，之后才能进入代码。

## 5. 技术采用与排除

工单中出现的 React 19、Redux Toolkit、Zustand、Tailwind CSS 和 React Native 不覆盖已经确认的 Vue 3、Pinia、Fabric.js 与 Java 后端选择。可以借鉴的只有以下工程原则：

- 状态集中管理和可测试的权限守卫。
- 配置驱动的会员权益、价格与授权说明。
- 虚拟化、节流和防抖等性能方法。
- 组件化的页面、表格、对话框和移动适配。
- 浏览器兼容性与性能验收标准。

不采用：复制竞品界面、截图、链接中的模板、价格、素材、账户流程或宣传文案。

## 6. 下一份规格的前置决策

下一阶段应先编写身份与后台基础规格，或者在身份工作前先编写编辑器规格。开始编辑器规格前，产品负责人必须明确：

1. 商家是否拥有自由添加/删除/移动元素的权限，还是仅编辑模板字段。
2. 哪些文字样式、图片滤镜和变换属于首版可用能力。
3. 高分辨率图片的限制、浏览器最低版本和性能阈值。
4. 协作是先做存在状态/锁定还是必须一次性做自动合并。
5. 非会员每日三次免费额度的计费对象和时区。

在这些决定完成前，当前工作台计划继续按原范围执行。
